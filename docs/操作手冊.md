# gen-doc 操作手冊

給第一次操作這套系統的人看的完整步驟。目前系統**沒有客製化的網頁前端**，功能透過 API（用 curl 呼叫）跟 Django 內建後台（`/admin/`）操作。本手冊涵蓋兩者。

---

## 0. 前置準備

### 0.1 啟動服務

```bash
cd D:\claude\gen-doc
.venv\Scripts\python src\manage.py runserver
```

看到 `Starting development server at http://127.0.0.1:8000/` 就代表啟動成功。

### 0.2 確認有登入帳號

沒有帳號的話，先建立一個（互動輸入帳密）：

```bash
.venv\Scripts\python src\manage.py createsuperuser
```

### 0.3 Windows 使用者請注意：curl 傳中文會出錯

在 Git Bash／PowerShell 裡用 `curl -d '{"name": "中文"}'` 直接傳中文字串，會觸發伺服器端 `UnicodeDecodeError`——這是 Windows 終端機把中文字串轉成非 UTF-8 位元組再傳出去的編碼問題，不是系統的 bug。

**解法**：先把 JSON 內容寫進一個 UTF-8 檔案，再用 `--data-binary @檔案路徑` 傳送，本手冊以下所有範例都採用這個寫法。

## 1. 登入（每次開新的 session 都要做一次）

所有會改變資料的 API 都需要先取得 CSRF token，並全程用同一個 cookie jar。

```bash
cd D:\claude\gen-doc

# 1-1 取得 CSRF token（同時把 cookie 存進 cookies.txt）
curl -s -c cookies.txt http://localhost:8000/api/auth/csrf/

# 1-2 把 token 讀出來存進變數，之後每個會改資料的請求都要帶上
TOKEN=$(python -c "import http.cookiejar; jar=http.cookiejar.MozillaCookieJar('cookies.txt'); jar.load(); print([c.value for c in jar if c.name=='csrftoken'][0])")

# 1-3 登入
curl -s -b cookies.txt -c cookies.txt -X POST http://localhost:8000/api/auth/login/ \
  -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json" \
  -d '{"username": "你的帳號", "password": "你的密碼"}'
```

看到 `{"detail": "登入成功", ...}` 就代表成功。之後每個範例指令都假設 `cookies.txt` 跟 `$TOKEN` 已經備好。

## 2. 建立專案

每接一個新客戶／新專案，第一步是建立專案並填基本資料。

```bash
cat > project.json <<'EOF'
{
  "customer_name": "客戶名稱",
  "project_name": "專案名稱",
  "system_name": "系統名稱",
  "system_url": "https://example.com",
  "system_version": "1.0",
  "acceptance_date": "2026-12-31",
  "install_environment": "正式環境",
  "operating_system": "RHEL 9",
  "database": "PostgreSQL 15",
  "server_location": "內湖機房"
}
EOF

curl -s -b cookies.txt -X POST http://localhost:8000/api/projects/ \
  -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json" \
  --data-binary @project.json
```

回傳的 JSON 裡的 `"id"` 就是這個專案的編號，後面所有步驟都要用到，以下範例用 `1` 代表。

**查詢所有專案**：`curl -s -b cookies.txt http://localhost:8000/api/projects/`
**查詢單一專案**：`curl -s -b cookies.txt http://localhost:8000/api/projects/1/`
**刪除專案**：`curl -s -b cookies.txt -X DELETE http://localhost:8000/api/projects/1/`（**真實刪除，不可復原**——資料列會直接從資料庫移除，且會一併永久刪除這個專案已產生過的所有文件歷史紀錄，刪除前請確認）

## 3. 內容模組管理（公司共用的功能庫，通常只需要建立一次）

這一段建立的是**所有專案共用**的產品功能說明（樹狀結構），跟特定客戶無關。已經建過的功能，之後每個新專案直接勾選使用即可，不用重做。

### 3.1 建立功能節點

```bash
cat > node.json <<'EOF'
{"name": "帳號管理", "description": "使用者帳號的新增/編輯/刪除"}
EOF
curl -s -b cookies.txt -X POST http://localhost:8000/api/feature-nodes/ \
  -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json" \
  --data-binary @node.json
```

回傳的 `"id"` 是節點編號。功能可以是樹狀結構——建立子節點時多帶一個 `"parent": <父節點id>` 即可，深度不限。

**查看所有節點（樹狀）**：`curl -s -b cookies.txt http://localhost:8000/api/feature-nodes/tree/`
**刪除節點**（**真實刪除，不可復原**——資料列連同這個節點的內容、各專案對它的勾選/排除紀錄都會一併永久刪除；若這個節點還有子節點會被擋下無法刪除，須先刪除或改接子節點）：`curl -s -b cookies.txt -X DELETE http://localhost:8000/api/feature-nodes/1/`

### 3.2 設定該節點在各文件類型的內容

四種文件類型代碼：`system_design`（系統設計文件）／`system_test`（系統測試文件）／`system_install`（系統安裝文件）／`training_deck`（教育訓練簡報）。

**系統設計/測試/安裝文件**用一整段文字（`body`）：

```bash
cat > content.json <<'EOF'
{"body": "本模組提供帳號的新增、編輯、刪除功能，操作網址為 {{project_variables.system_url}}。"}
EOF
curl -s -b cookies.txt -X PUT "http://localhost:8000/api/feature-nodes/1/contents/system_design/" \
  -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json" \
  --data-binary @content.json
```

文字裡可以放 `{{project_variables.系統網址}}` 或 `{{project_variables.system_url}}` 這種佔位符，正式產生文件時會自動換成該專案填的實際值；如果專案沒填這個變數，產生前會被擋下並列出來提醒你。

**教育訓練簡報**用條列陣列（`bullets`），不是整段文字：

```bash
cat > training.json <<'EOF'
{"bullets": ["點選「新增帳號」按鈕", "輸入帳號、密碼、權限", "點選「儲存」完成新增"]}
EOF
curl -s -b cookies.txt -X PUT "http://localhost:8000/api/feature-nodes/1/contents/training_deck/" \
  -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json" \
  --data-binary @training.json
```

### 3.3 設定該節點需要哪些截圖

```bash
cat > requirement.json <<'EOF'
{"name": "帳號列表畫面"}
EOF
curl -s -b cookies.txt -X POST "http://localhost:8000/api/feature-nodes/1/screenshot-requirements/" \
  -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json" \
  --data-binary @requirement.json
```

一個節點可以設定多個截圖需求（例如「帳號列表」「新增帳號」「刪除確認」各建一筆）。

## 4. 功能選擇（針對這個專案，勾選要用哪些功能）

```bash
cat > selection.json <<'EOF'
{"checked": [1, 2], "excluded": []}
EOF
curl -s -b cookies.txt -X PUT "http://localhost:8000/api/projects/1/feature-selection/" \
  -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json" \
  --data-binary @selection.json
```

- `checked`：勾選的節點 id（勾選一個節點會**自動包含它所有子節點**，不用逐一勾）
- `excluded`：如果某個子節點客戶沒有用到，把它的 id 放進這裡個別排除，其餘子節點不受影響

**每次都要送完整清單**（這是整組覆蓋，不是逐一加減）。

**查詢目前的勾選狀態與實際生效清單**：`curl -s -b cookies.txt http://localhost:8000/api/projects/1/feature-selection/`

## 5. 截圖管理

### 5.1 查看這個專案的截圖待辦清單

```bash
curl -s -b cookies.txt http://localhost:8000/api/projects/1/screenshots/
```

會列出目前已勾選功能所需要的所有截圖，並標示「已完成」或「尚未上傳」。

### 5.2 上傳截圖（預設版本，套用所有文件類型）

```bash
curl -s -b cookies.txt -X POST "http://localhost:8000/api/projects/1/screenshots/<截圖需求id>/default/" \
  -H "X-CSRFToken: $TOKEN" \
  -F "image=@/path/to/screenshot.png"
```

### 5.3 上傳客製版本（只套用特定文件類型，例如教育訓練簡報要加註標示）

```bash
curl -s -b cookies.txt -X POST "http://localhost:8000/api/projects/1/screenshots/<截圖需求id>/custom/" \
  -H "X-CSRFToken: $TOKEN" \
  -F "image=@/path/to/annotated.png" \
  -F "document_types=training_deck"
```

客製版本跟預設版本**互不影響**，可以同時存在。

## 6. 內容覆寫與自訂章節（選用，多數專案不需要）

### 6.1 針對這個專案覆寫某節點在某文件類型的內容

```bash
cat > override.json <<'EOF'
{"body": "本專案的帳號管理採用 SSO 單一登入，不使用傳統帳密驗證。"}
EOF
curl -s -b cookies.txt -X PUT "http://localhost:8000/api/projects/1/content-overrides/1/system_test/" \
  -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json" \
  --data-binary @override.json
```

只影響**這個專案、這個節點、這個文件類型**，其他文件類型跟其他專案都還是用共用預設內容。

**移除覆寫（改回用共用預設）**：`curl -s -b cookies.txt -X DELETE "http://localhost:8000/api/projects/1/content-overrides/1/system_test/"`

**（後台管理用）查看某個功能節點目前被哪些專案覆寫過**：
`curl -s -b cookies.txt "http://localhost:8000/api/feature-nodes/1/overrides/"`
這只是給你參考、決定要不要手動同步共用內容用的唯讀清單——**修改共用內容不會自動更新既有的覆寫**，兩者是分開的。

### 6.2 新增專案專屬的自訂章節（不對應任何功能節點）

```bash
cat > section.json <<'EOF'
{"title": "資安聲明", "content": "本系統已通過 ISO 27001 認證。"}
EOF
curl -s -b cookies.txt -X POST "http://localhost:8000/api/projects/1/custom-sections/" \
  -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json" \
  --data-binary @section.json
```

## 7. 文件預覽與產生前檢查

### 7.1 預覽組裝結果

```bash
curl -s -b cookies.txt "http://localhost:8000/api/projects/1/preview/system_design/"
```

會回傳這份文件目前的完整章節內容（含變數替換後的文字、截圖）。可以用的 `document_type` 同第 3.2 節的四種代碼。

### 7.2 調整章節順序／排除某章節／換截圖／改圖說

```bash
cat > adjust.json <<'EOF'
{"section_order": ["node:2", "node:1"], "excluded_sections": []}
EOF
curl -s -b cookies.txt -X PUT "http://localhost:8000/api/projects/1/preview/system_design/adjustments/" \
  -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json" \
  --data-binary @adjust.json
```

調整會被記住，下次再打開預覽還是這個順序。**注意這個排序是「每種文件類型各自一份」**，系統測試文件跟教育訓練簡報的順序互不影響。

同一個端點還可以帶 `screenshot_selections`（手動指定某個截圖需求要用哪一張圖，覆蓋系統自動判斷）跟 `caption_overrides`（覆蓋某張截圖的圖說文字），格式都是 `{"截圖需求id": 值}` 的物件，只送有要改的欄位即可，不會清掉其他欄位已經存的設定。

### 7.3 產生前檢查（缺截圖或缺變數會在這裡看到）

```bash
curl -s -b cookies.txt "http://localhost:8000/api/projects/1/preview/system_design/validate/"
```

`"ready": true` 才能產生；如果是 `false`，`missing_screenshots`／`missing_variables` 會列出具體缺什麼。

## 8. 正式產生文件

### 8.1 產生 DOCX（系統設計／系統測試／系統安裝）

```bash
curl -s -b cookies.txt -X POST "http://localhost:8000/api/projects/1/documents/system_design/generate/" \
  -H "X-CSRFToken: $TOKEN" \
  -o "系統設計文件.docx"
```

`document_type` 換成 `system_test`／`system_install` 就能產生另外兩類文件。

### 8.2 產生 PPTX（教育訓練簡報）

```bash
curl -s -b cookies.txt -X POST "http://localhost:8000/api/projects/1/documents/training_deck/generate/" \
  -H "X-CSRFToken: $TOKEN" \
  -o "教育訓練簡報.pptx"
```

如果 7.3 的檢查沒過（缺截圖／缺變數），這裡會被擋下並回傳明確錯誤，不會產出殘缺的文件。

### 8.3 查詢產生歷史

```bash
curl -s -b cookies.txt "http://localhost:8000/api/projects/1/documents/system_design/history/"
```

同一份文件每次重新產生都會**新增一筆歷史紀錄**，不會覆蓋舊的——之後想找回上一版的內容仍然找得到。

### 8.4 查詢專案列表的文件產生狀態（四類文件是否都已產生）

```bash
curl -s -b cookies.txt "http://localhost:8000/api/projects/documents-status/"
```

## 9. 複製專案（下一個類似客戶時可以省很多步驟）

```bash
cat > duplicate.json <<'EOF'
{"customer_name": "新客戶名稱", "project_name": "新專案名稱"}
EOF
curl -s -b cookies.txt -X POST "http://localhost:8000/api/projects/1/duplicate/" \
  -H "X-CSRFToken: $TOKEN" -H "Content-Type: application/json" \
  --data-binary @duplicate.json
```

**會複製**：功能勾選、排除清單、內容覆寫、自訂章節、預覽設定。
**不會複製**：截圖（新專案的截圖全部回到「尚未上傳」）、其他專案變數（只有你上面指定的客戶名稱／專案名稱會填，其餘要重新輸入）、產生歷史。

---

## 10. 用 Django 後台（/admin/）瀏覽資料

不想每個查詢都打 API 的話，可以用瀏覽器登入 `http://localhost:8000/admin/`（帳密同第 1 節），用圖形介面瀏覽/搜尋 Project、FeatureNode、ProjectScreenshot、GeneratedDocument 等資料表。

**注意**：`GeneratedDocument`（產生文件的歷史紀錄）**不要**在後台手動「新增」——這張表的內容（產生時的完整內容快照、實際檔案）是系統呼叫 8.1／8.2 的產生 API 時自動寫入的，手動填會因為欄位對不上而跳「請修正以下錯誤」。想要新增一筆歷史紀錄，請走第 8 節的產生流程。

## 附錄：完整流程速查（新客戶從零到產生文件）

1. 登入（第 1 節）
2. 建立專案（第 2 節）
3.（如果功能庫已經建過就跳過）建立功能節點與內容（第 3 節）
4. 勾選這個專案要用的功能（第 4 節）
5. 上傳截圖，直到 `documents/status` 或 `screenshots/` 顯示全部完成（第 5 節）
6.（選用）內容覆寫／自訂章節（第 6 節）
7. 預覽確認、產生前檢查 `ready: true`（第 7 節）
8. 產生四類文件（第 8 節）
